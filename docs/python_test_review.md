# Python matching test value review

The Rust contract in `docs/rust_matching_core_contract.md` governs migration. The reviewed legacy source is commit `f3fa73a84a655eace51d0bb4140e6ed9c534b7ce` at `reference/python/tests`, available through Git history after retirement. The Python tests were assessed for observable behavior and failure risk, rather than test count or one-for-one parity. Existing Rust coverage includes a command model oracle (`audit_matching.rs`), state and capacity checks (`core.rs`, `audit_edges.rs`), snapshot and replay checks (`snapshot.rs`, `audit_integration.rs`), and the full default-capacity sweep (`core.rs`, `default_sweep_execution.rs`).

| Python module | Assessment and decision |
| --- | --- |
| `test_types.py` | Enum integer values, arithmetic, uniqueness, and ordering are Python representation checks. Rust uses typed `Side` and `OrderStatus`; `types.rs` checks side behavior and public serialization. No migration. |
| `test_structures.py` | Field storage, `msgspec` immutability, mutable `Order.size`, and empty response construction test the Python container implementation. Rust owns separate typed records and bounded response storage; `types.rs` and `core.rs` cover public fields and response behavior. No migration. |
| `test_price_level.py` | FIFO append, middle removal, partial reduction, aggregate updates, and empty level removal matter. `core.rs` and `audit_matching.rs` verify them through public commands on both sides; `arena.rs` unit tests cover slot mechanics. Avoid duplicating private `order_map`, `peek_front`, and `pop_front` mechanics. |
| `test_orderbook.py` | Best price, ordered level traversal, spread equality, and reached self-trade are valuable. The Rust model oracle checks book views after every command; `core.rs` and `audit_matching.rs` exercise FIFO, crossing, and late self-trade. Added directed limited-depth transitions on both sides in `behavior_gaps.rs`; no private index parity tests. Python's first conflicting client ID is not part of the Rust `SelfTrade` error contract. |
| `test_engine_queries.py` | Live order lookup, best prices, level aggregates, and ordered depth are public behavior. Existing `core.rs` and model checks cover normal lookups, empty values, and full/one-level depth. Added depth of two while three levels exist on each side, checking price, size, and count before and after levels disappear. Python's global client-ID lookup differs from Rust's account-scoped identity. |
| `test_engine_makers.py` | Add, cancel, amend, FIFO reset, capacity, response order, and client-ID reuse are important. Existing `core.rs`, `audit_edges.rs`, and `audit_matching.rs` cover nearly all. Added crossing amend rejections on both sides, size just outside each bound, accepted exact min/max sizes, and complete snapshot/identity checks. Also added identical-value amendment, which must still receive a fresh ID and lose FIFO priority. Rust assigns fresh public IDs and FIFO priority on every successful amend. |
| `test_engine_takers.py` | Price-time matching, maker-price fills, partial remainders, price limits, reached-only self-trade, and no-liquidity errors are important. Existing `core.rs`, `audit_matching.rs`, and full sweep tests cover them, including rejection atomicity and response completeness. Added the post-fill client-ID release in an integrated query flow. Rust deliberately leaves counters unchanged on no liquidity; Python currently advances them. Python's conflicting client ID in `SelfTradeError` is not a Rust contract. |
| `test_engine_snapshot.py` | Snapshot state, FIFO, counters, and continued execution are important. `snapshot.rs` validates export/restore and malformed inputs; `audit_integration.rs` compares continued execution after restore at every boundary. No additional parity cases. |
| `test_integration.py` | Mixed command flows, deterministic replay, aggregate consistency, and realistic book exhaustion are valuable. `audit_matching.rs` uses an independent model for mixed streams; `audit_integration.rs` checks restore/replay and execution pressure; full default limits are exercised explicitly. Added one concise fill/reuse/query flow. Midpoint arithmetic and Python private map assertions do not describe Rust matching behavior. |
| `conftest.py` | Shared fixture only; no behavior to migrate. |

## New directed checks

`crates/matching-core/tests/behavior_gaps.rs` covers three retained gaps: (1) crossing or out-of-range amendments leave the book, account/client mappings, and counters unchanged, followed by valid replacements at the exact size bounds; (2) filling a maker removes its order and releases its account-scoped client ID while best prices and limited bid/ask depth advance through later add, cancel, and fill commands; (3) an identical-value amend still replaces the public ID and resets FIFO priority.

The review intentionally does not copy Python test structure, private storage assertions, Python numeric/string representations, or repeated single-field response assertions. Rust's exact integer units, engine-scoped order IDs, account-scoped client IDs, bounded capacity, and rejection atomicity take precedence wherever the contracts differ.
